### VPN: Virtual Private Network

- 仮想の専用回線を構築
  - => 暗号化されたセキュアな通信
- 機能
  - トンネリング
  - カプセル化
    - **別のプロトコルのデータとして包まれて送受信**
  - 暗号化
  - 認証
- 種類
  - IP-VPN
    - **通信事業者が独自に保有**する閉域ネットワーク
    - インターネット VPN より安全
      - 第三者は接続できない
    - 暗号化はあまり必要ない
      - => 高速化のためにしない傾向にもある
  - インターネット VPN
    - 一般の回線上に VPN トンネルを仮想的に構築
    - 安価で導入しやすい
    - 暗号化必須
- 認証
  - 3要素
    - 知識
    - 所有
    - 生体
  - PKI: 公開鍵基盤
    - 公開鍵暗号方式を利用して**個人や組織の信頼を確保するための社会きばん**
    - CA に証明書を発行してもらう

## 2

- Emotet
  - アクセスされるたびにコードが変わる
    - => シグネチャーベースのスキャンでは検知できない
  - スキャンされることを検知して動作を停止させる
    - => 振る舞い検知でも防ぐことが難しい
  - Emotet それ自体に不正なコードはほとんどない
  - **ローダー（ダウンローダー）のツール群**
    - **本体には不正な機能がない！**
    - マクロ経由で侵入
  - ほぼ壊滅？
    - C&C サーバーインフラが停止した？
- PPAP:
  - 略
    - Password 付き Zip
    - Password 送る
    - Angoka Protocol
  - **パスワードをかけて暗号化されたファイルはセキュリティスキャンできない**
  - **PPAP は送付先にセキュリティリスクを与える行為**でしかない
    - すぐやめよう
    - そもそも総当たり攻撃で必ず復元できるので漏洩防止にならない
    - TLS 暗号化のみでほぼ十分

## 5

- ユーザー認証
  - **本人確認のしくみの一部**
    - Identity Verification
    - Know Your Customer
- **本人確認**
  - **当人認証** Authentication
    - 登録済みの利用者であることの確認
    - 識別
      - メールアドレス
      - 電話番号
      - サービスない識別し
    - 検証
      - パスワード
      - OTP
  - **身元確認** Identity Proofing
    - 属性情報の検証
    - 対象
      - メールアドレス
      - 電話
      - 基本４情報
    - 方法
      - OTP/リンク
      - 画像・動画
      - 公的個人認証
- パスワード認証
  - パスワードは**検証**のところ
  - 特徴
    - クロスデバイス環境
      - 特定の端末に依存しない
    - クロスプラットフォーム環境
  - 課題
    - 運用難易度
    - 脆弱性
  - パスワードマネージャー
    - メリット
      - 推測困難な文字列の自動生成
      - パスワードの保存・管理
      - 登録時ドメインを利用した自動入力
        - フィッシングサイト対策
    - 課題
      - **ユーザーに強制できない**
  - **リスクベース認証**
    - 普段と異なる環境からのアクセスを検出
    - => 必要に応じて追加の認証を求める
- **認証要素**
  - Something You Know: SYK
  - Something You Have: SYH
    - OTP, TOTP
    - メール・SMS 受信
    - 故障・紛失・変更時の考慮が必要
  - Something You Are: SYA
    - 顔、指紋、虹彩など、**ローカル認証の利用**も
    - リカバリーの課題、偽陽性、偽陰性
    - **生体情報がデジタルデータとして第三者に盗まれた場合、ユーザー側で変更できない**
- 多要素認証の普及
  - 導入コストの低下
  - 多要素認証が利用できない状況は発生しうる
    - **=> CS の負担増加**
    - **=> バックアップコードを提供し、緊急時に認証を続行可能に**
      - これって SYH になるのかな、SYK ではない？
- 多要素認証の新たな課題
  - **中継型フィッシング**
    - ログイン後のセッション情報を取得
      - 攻撃の方法が変わってきた
    - **それぞれの認証方式がフィッシング耐性を持っていない**ことに起因
  - フィッシング耐性のある認証
    - パスワードマネージャー
    - WebOTP
      - SMS で受信したワンタイムパスワードをブラウザが取得する
      - https://developer.mozilla.org/ja/docs/Web/API/WebOTP_API
      - **OTP 自体をドメインに紐づける**
- 安全性と利便性を兼ね備えた認証方式
  - 認証要素やフィッシング耐性
  - **パスワードレス認証**
    - **メールのログイン認証としてログイン URL 送信を当人認証とする**
      - => 所持情報の強度が不十分
        - デバイス・環境が複数存在している
      - プロバイダへの依存
        - メール受信環境自体のせいキュリティ課題もある
- FIDO 認証
  - **ファイド**
  - パスワードレス認証方式の１つ
  - FIDO アライアンス + W3C で仕様の策定
  - 登場人物
    - サービス
      - Web サービス
      - Relying Party: RP
    - デバイス
      - ユーザーが所持し、認証に必要な情報（秘密鍵等）を管理するデバイス
      - 認証器 Authenticator と呼ばれる
    - ブラウザ
      - サービスから FIDO 認証を要求され、認証器とやり取りをする
      - クライアント Client
  - 公開鍵暗号方式
    - **ID 管理の技術では、暗号・復号よりもデジタル署名の生成・検証にとっての方が重要な役目！**
    - デジタル署名
      - 送信者
        - 送信するデータ + メタデータ => 秘密鍵でデジタル署名作成
      - 受信側
        - 公開鍵での検証
- **FIDO しくみ**
  - デバイス内にある安全な領域に秘密鍵を保存
    - FIDO クレデンシャル
      - 秘密鍵 + サービス + ユーザー情報
    - 公開鍵をサービスが保持する
  - デバイスによる認証
    - サービスが認証要求とともにチャレンジを生成
    - デバイスは秘密鍵を用いてチャレンジを含むデバイス署名を生成, 返答
      - 生成に進む条件として、**ローカル認証を要求**
    - サービスはそのデジタル署名を公開鍵で検証
- **FIDO のメリット**
  - 秘密鍵がネットワークを流れない
  - サービスごとの鍵ペアが生成される
- **FIDO 課題**
  - デバイス紛失・故障・機種変更時のリカバリー問題
    - => 複数デバイス登録という対策
  - => パスキー認証
- **パスキー**
  - FIDO 認証の仕様を拡張
    - シームレスなパスワードレス認証
      - 全てのデバイスで再登録が不要
    - クロスデバイス環境での認証の簡便化
  - **FIDO クレデンシャル => パスキー**
    - **パスキーはパスワードマネージャーに保存**
    - **FIDO 認証が主張してきた堅牢性を一部緩和**
    - デバイスやプラットフォームを超えたパスキーの同期
      - => リカバリー問題の解決
- パスキー
  - **FIDO2**
    - WebAuthn
    - CTAP
      - Client-To-Authenticator Protocol
      - 認証器とクライアントの通信仕様
